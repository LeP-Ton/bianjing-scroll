## 约束与原则

- 源 JPG 原字节保留，不降采样、不做第二次有损编码。
- 源文件本身是 JPG，已有原先的编码压缩；“无损切片”仅表示与源图解码像素完全一致，不声称原 JPG 本来无损。
- 以原始 `38414 × 1800` 像素作为唯一世界坐标，画面、命中和提示一致换算。
- 网页继续保持静态、无构建及无 npm 运行依赖。
- 小地图和全览缩略图保留导航用途，不用作主图细节来源。

## 关键实现说明

- `manifest.js` 直接将清单赋给 `window.RUHUA_ARTWORK`；它与图片层、应用脚本顺序执行，直接打开本地 HTML 时不依赖 `fetch` 读取 JSON。
- `tiles.json` 与脚本清单内容一致，保留给素材检查和工具读取。
- 当前视野内的图片优先加载，全部就绪后才请求邻近切片。常规缓存为 6 片；视野与邻近必要片数超过此值时保留必要片数，释放无关节点。
- 切片使用实际原图 `x/y/width/height` 定位；边缘重叠像素来自原图，不对画面补画或插值。
- `1:1` 提供原图像素查看；界面常规 `100%` 仍是适配画卷容器高度，不等同于原始像素一比一。
- 原图下载指向未重新编码的 JPG，便于用户直接核对源文件。
- 移除主图颜色滤镜与纸纹覆盖，界面的绢纸、朱印等装饰保留在界面层。

## 重新生成

需要 Node 与独立工具目录中可用的 `sharp`。本次使用运行环境已提供的 `sharp`，未安装到项目，也未新增 npm 运行依赖。

```sh
node scripts/prepare-artwork.mjs --source "dist/assets/qingming-original.jpg" --sharp-module "C:/工具目录/node_modules/sharp"
```

工具环境已能解析 `sharp` 时可省略 `--sharp-module`；`--source` 也可传入其他位置的同一源 JPG。脚本验证尺寸、原图副本、每片像素和整卷重拼，任何不一致均中止，不生成声称成功的清单。

## 关键风险

- 无损切片总量大于源 JPG，需要按视野调度；不能一次性加载整卷所有切片。
- 缩放、拖拽或跨卷切换后，需要确认画面已加载范围与热点坐标一致。
- 需要检查切片边界、离开视野后的释放、预取顺序与失败重试，避免出现空白或缓存无限增长。
- 文件直接打开与 GitHub Pages 仓库子路径都需要使用正确的相对资源地址。
- 浏览器仍会按当前显示比例采样；原分辨率资源保证保留了可供查看的原图细节，不意味着任何屏幕比例都显示全部像素。
