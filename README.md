# 入画 · 汴京寻物

在《清明上河图》中寻物，读一段宋人日常。

[在线游玩](https://lep-ton.github.io/bianjing-scroll/) · [GitHub 仓库](https://github.com/LeP-Ton/bianjing-scroll)

## 打开游戏

直接使用浏览器打开 `dist/index.html`，即可开始游玩。

也可以在本目录运行：

```sh
node server.mjs
```

再打开 http://localhost:4173。无需安装依赖，无需构建。

## 资料与图像

主画卷使用用户提供的图像，物件点位经局部核对。斗笠、器皿等细节不作材质或窑口鉴定。

### 高清画卷

主画卷保留原图的 **38414 × 1800** 分辨率。原始 JPG 按原字节保存，查看与下载入口位于“画卷长览”。画中缩放控件提供 `1:1` 原图像素查看；常规的 `100%` 仍表示适配当前画卷高度。

为按需加载，画卷在原始像素中切成 21 片无损 WebP。切片不降采样、不做第二次有损编码；逐片解码和整卷重拼均已验证与源图解码像素一致。**源文件本身为 JPG，已有其原先的编码压缩，不能称为源图本来无损。**

当前视野优先加载，完成后再预取邻近切片；移步时释放不再需要的图片，常规缓存 6 片，视野与邻近必要片数较多时相应保留。加载失败可在画卷中重试。小地图与全览中的缩略图仅用于导航，不用于主图细节显示。

### 重新生成切片

日常运行与部署无需安装任何依赖。仅重新生成素材时需要独立工具目录中的 `sharp`，可通过参数指定它的模块路径：

```sh
node scripts/prepare-artwork.mjs --source "dist/assets/qingming-original.jpg" --sharp-module "C:/工具目录/node_modules/sharp"
```

如果当前工具环境已能解析 `sharp`，可省略 `--sharp-module`。脚本只解码、按原始像素裁切和无损编码，并核对原图文件哈希、每片像素与整卷重拼像素；生成 `dist/assets/painting/manifest.js` 和 `tiles.json`。切片的 1920 像素步长两侧各保留 1 像素重叠，用于避免缩放时出现拼缝。

字体优先使用系统宋体；在线时可加载 Noto Serif SC，字体不可用不影响游玩。

## 发布

网页由 GitHub Pages 托管，部署目录为 `dist/`。推送 `main` 上的网页或工作流变更后，GitHub Actions 会检查脚本、上传网页并部署；也可在 Actions 页面手动运行“部署汴京寻物”。

部署检查包括应用脚本、切片加载脚本和画卷清单的 JavaScript 语法；图片已在仓库中准备好，发布时不重新编码。

所有本地资源均使用相对路径，兼容 GitHub Pages 的仓库子路径。没有构建步骤，也不需要 npm 或 Jekyll。初次配置仓库时，Pages 的构建来源需要设为 GitHub Actions。
