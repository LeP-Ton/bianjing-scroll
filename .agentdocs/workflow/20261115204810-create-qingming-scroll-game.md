## 关键实现说明

- 寻物、提示和百科共用物品数据，避免同一物品名称、点位和内容产生分歧。
- 画卷坐标需与缩放和拖拽变换一致，避免视觉位置与点击位置错位。
- 三卷任务分别为六、四、四处，共十四处进度。货船在第一、二卷各出现一次，因此实际可寻得并收录的物件种类为十三种。
- `objects` 共十七条百科：十三种任务物件，以及供延伸阅读的虹桥、柳树、街铺、编篮。分类包括服饰、饮食、交通、建筑、商业、器具和风物；“已收录”筛选只展示已经寻得的物件。
- Web Audio API 需在用户操作后启动；默认体验不依赖声音。
- `localStorage` 保存当前浏览器进度；恢复时要求发现记录为普通对象，并过滤当前任务白名单和非 `true` 值，避免损坏或旧版数据阻断寻物。
- 发现百科的延迟回调保留计时器与触发关卡，切关取消回调，避免新关出现旧物百科。
- 画卷使用 `overflow:clip` 防止焦点引起独立内部滚动；键盘聚焦热点时主动定位物件，保持图像与点击坐标一致。

百科区分画面可见形态、场景用途推断和馆藏延伸鉴赏，不把细部难以辨认的材质或身份写成画面鉴定结论。

## 关键风险

- 原画较长，必须控制图像体积和缩放清晰度，避免初次加载或移动端卡顿。
- 细小物件难以准确辨认，点位和百科应明确可见事实与背景推断。
- 拖拽、触控缩放、点击发现可能互相冲突，需验证手势阈值和命中范围。
- 宽窄屏布局、键盘焦点与减少动态效果偏好需兼顾。
- 发布检查与本地预览属于不同环境，不能以本地成功代替发布成功。
